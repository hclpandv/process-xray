What Does This State Mean?

READY

The process is runnable and eligible for CPU time, but another task may currently be using the CPU.


fork() — Create a Process

PROCESS CREATION

fork() creates a new process by duplicating the calling process. The parent receives the child's PID, while the child receives 0 as the return value.

pid_t pid = fork(); if (pid == 0) { // child process printf("I am the child\n"); } else { // parent process printf("child PID = %d\n", pid); }

Try the controls to simulate fork() → execve() → scheduling.

execve() — Load a New Program

PROGRAM IMAGE

execve() replaces the current process image with another executable. The PID normally stays the same, but the program code, data, stack, and other memory mappings are replaced.

execve( "/bin/ls", argv, envp ); // PID remains the same // program image changes

The PID stays 4242 while the program image changes.

Signals and Process Control

kill(2)
SIGSTOP Suspends the process. It cannot be caught or ignored.
SIGCONT Continues a stopped process so it can become runnable again.
SIGTERM Requests graceful termination. The process may handle it.
SIGKILL Forces termination. It cannot be caught or ignored.
SIGCHLD Sent to a parent when a child changes state, including exit.
waitpid() Lets a parent collect a child's exit status and reap it.

Try It on Real Linux

The interactive lab above is simulated. These commands can be used on an actual Linux machine to inspect real processes.

# list processes ps aux # process tree pstree -p # inspect a process cat /proc/<PID>/status # inspect memory mappings cat /proc/<PID>/maps # send SIGSTOP kill -STOP <PID> # continue kill -CONT <PID> # terminate kill -TERM <PID> # inspect open files ls -l /proc/<PID>/fd

Important distinction

A stopped process is still alive. A zombie process has already terminated but its parent has not collected its exit status. Reaping removes the zombie's remaining process-table entry.


EXITED

TERMINATED

The process has finished executing. Conceptually, this is the point where the program's execution is over.

ZOMBIE

WAITING FOR PARENT

The child has exited, but the parent has not yet collected the child's exit status using a wait-family system call.

REAPED

CLEANED UP

The parent calls wait() or waitpid(). The exit status is collected and the zombie disappears.
